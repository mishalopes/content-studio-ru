# Карусели: отдельные слайды и анимация

## Обязательный результат

Запрос «сделай/нарисуй карусель» выполнять как набор готовых отдельных слайдов,
а не как одну картинку с миниатюрами всех страниц. Один слайд = один отдельный
файл и одна отдельная доступная пользователю выдача. Не подменять результат
сценарием, презентацией, PDF, общей сеткой или контактным листом.

Для статичной карусели выдавать slide-01.png … slide-NN.png либо JPG согласованного
качества. Все слайды должны иметь одинаковые размеры, соотношение сторон и
последовательную нумерацию. Если пользователю нужен другой формат, следовать ему.
Для анимированной карусели выдавать slide-01.mp4 … slide-NN.mp4, а также отдельные
статичные превью slide-01.png … slide-NN.png. Смешанный набор допустим по брифу,
но тип каждого элемента должен быть понятен из манифеста.

Общий контактный лист использовать только для внутренней проверки или как
дополнительное превью с явной подписью. Архив может дополнять выдачу, но не
заменять отдельные доступные файлы, если пользователь не попросил иначе.

## Сначала выбрать маршрут

Обычную карусель делать статичной. По просьбе об анимации использовать анимированный
маршрут. Если пользователь просит «оживить эту карусель», использовать существующие
слайды и сохранять утверждённые тексты, число страниц и порядок, кроме явно
запрошенных изменений. Не добавлять платную генерацию видео без основания в задаче.

Взять доступный профиль бренда и референсы. При новом проекте выбрать оформление
под аудиторию и цель; не переносить автоматически шрифты, цвета и личные данные
автора этого навыка. Количество слайдов определять по мысли и запросу.
Для Instagram ориентир макета — 1080×1350 (4:5), если другой формат не согласован.
Это рабочее значение, не утверждение о единственном разрешённом формате платформы.

## Содержание и дизайн

Составить таблицу: номер, заголовок, основной текст, визуал, альтернативный текст,
для анимации — движение, длительность и финальная пауза. Первый слайд раскрывает
тему и вызывает интерес. Каждый следующий развивает мысль, содержит одну основную
идею и читается самостоятельно. Финал закрывает обещание или даёт уместный шаг.
Не навязывать CTA, когда материал в нём не нуждается.

Использовать крупные заголовки и ясную иерархию. На 1080×1350 держать важный текст
внутри полей 90–120 px как начальный ориентир, проверяя фактическую вёрстку.
Первую страницу отличать от предыдущих публикаций композицией, сценой, углом или
светом; сохранять узнаваемый бренд. Числа, цитаты и утверждения проверять по
материалу автора. Подпись к публикации дополняет карусель, а не пересказывает её.
Имена авторов шрифтов и названия шрифтов не добавлять как декоративный текст
слайда; лицензионные сведения хранить в сопроводительных материалах по условиям.

## Создание отдельных изображений

Для иллюстраций применять доступный инструмент генерации/редактирования изображений.
В запросе на генерацию явно указывать: один готовый слайд, один холст, его номер,
полный текст и параметры общего дизайна. Для следующих слайдов использовать
утверждённый референс и параметры серии. Изменение одной страницы не должно
перегенерировать остальные без необходимости.

Если инструмент умеет выдать несколько независимых изображений за вызов,
проверить, что это действительно отдельные файлы, а не единая сетка. При получении
коллажа заново создать слайды по отдельности. Не считать произвольную обрезку
общей картинки полноценной восстановленной каруселью: она может потерять размер,
поля, текст и композицию. Разделение уже готового листа делать только когда
пользователь просит именно это, с проверкой границ каждого результата.

Для точного длинного текста можно сгенерировать иллюстрацию отдельно, а надписи
наложить средствами вёрстки с реальными шрифтами. Не считать текст безошибочным
лишь потому, что он был указан в промпте. Проверить каждую букву, переносы,
пунктуацию и порядок слайдов на фактических изображениях.

## Анимация по слайдам

Выбрать Remotion или HyperFrames для управляемых текстовых и графических слоёв;
Lemo/MG — для художественной техники. Читать animation-direction.md,
motion-design.md, remotion.md или hyperframes.md по задаче. Внешние движки
должны быть отдельно доступны и проверены.

У каждого слайда создать собственную композицию/таймлайн и отдельный экспорт.
Варианты движения: раскрытие заголовка, пословные смысловые акценты, бумажные
вырезки, параллакс, движение персонажа, появление схемы, лёгкий push/pull камеры.
Не чередовать одинаковый эффект механически на всех страницах. Если исходник
плоский, не обещать независимое движение объектов без разделения на слои.

Показывать основную мысль сразу или достаточно рано, затем оставлять время чтения.
Длительность подбирать по объёму текста и движению; 4–8 секунд — лишь начальный
ориентир для короткой страницы, не обязательный лимит. Проверять фактическую
читаемость и требования выбранного способа публикации. Не ускорять текст ради
шаблонной длины. Зацикливать мягко, если это уместно, без обрыва слов и скачков.
Звук добавлять по брифу; смысл должен оставаться понятным без звука.

Для MP4 ориентир экспорта: H.264, yuv420p, единый fps, одинаковое разрешение;
AAC при наличии аудио. Длительность и кодеки сверять с актуальной площадкой
и коннектором перед отправкой. GIF не подменяет MP4 для публикации.
Неподвижная картинка в MP4 не считается анимированным слайдом. Один общий ролик
со всеми страницами можно выдать дополнительно по запросу; он не заменяет
отдельные MP4, по которым пользователь листает карусель.

## Контроль и выдача

Проверить количество файлов против таблицы и стабильные номера 01…NN.
Статичные изображения: размер, ориентация, текст, поля, согласованность персонажей,
палитры и шрифтов. Анимация: просмотреть начало, ключевое движение и конец каждого
клипа; проверить длительность, звук, декодирование и читаемость последнего состояния.
Контактный лист помогает увидеть серию, но не заменяет просмотр каждой страницы.

Сохранить manifest.json с номером, типом (image/video), именем файла, текстом,
альтернативным текстом, размером и длительностью для видео. Добавить caption.txt.
Сохранить результаты через штатный механизм среды. В ответе показать каждый
слайд отдельно, по порядку, с отдельной загрузкой/превью. Если инструмент уже
показывает и сохраняет каждое сгенерированное изображение, использовать этот
механизм без ненужного дублирования. Не сообщать о готовности, пока отдельные
файлы не созданы и не доступны пользователю.

## Публикация

Создание карусели не означает её публикацию. По поручению на отправку проверить,
поддерживает ли текущий аккаунт и коннектор изображения, видео и смешанные элементы
в одной карусели. Проверить актуальные ограничения и порядок media. Загрузить
каждый слайд отдельным media-элементом, а не контактный лист или архив.
Не заменять карусель единым Reel молча. При ограничениях коннектора выдать
готовые отдельные файлы и сообщить конкретное ограничение отправки.
